# ADR-189: Sirus Native, a GPUI window over the headless host

- Status: accepted
- Date: 2026-11-05

## Context

The Tauri and React window has the features people use, but scrolling long conversations and animating tabs cost more than a native renderer would. A throwaway test of the Monocode tab strip in GPUI (Rust and Metal) felt faster, so the window is being rewritten in stages. The functionality stays the same as Sirus Code; design and layout are what change.

## Decision

- **Separate app.** `native-spike/` builds "Sirus Native" with its own app id (`com.siruscode.native`) and data folder, beside Sirus Code. The first run copies the data with `sqlite3 .backup`, with automatic work off.
- **Same back end.** The window starts `sirus-host` (ADR-131) on `127.0.0.1:7811` (the window's own listener, see "Remote access" below) and speaks the phone's WebSocket protocol (ADR-080). It adds no commands of its own, apart from routing the visual tools (`visual_docs`, `visual_check`, `visual_show`) in `browser_mcp.rs` and storing a visual's native source.
- **Its own secrets.** With `SIRUS_KEYCHAIN_APP` set, the host keeps connector tokens and browser logins under that app's Keychain items. It copies a Sirus Code item only when macOS allows it without asking, and never writes back. Sharing items made each app rewrite the other's secrets, and macOS then asked for the password.
- **Vendored GPUI.** `vendor/gpui-pre*` comes from Monocode's upstream, for its frosted backdrop and rounded clips. Licences are kept in `LICENSE-MONOCODE-MIT` and `ICONS-NOTICE.md`.
- **Virtual transcript.** A conversation is a `gpui::list` that builds only the turns on screen and follows the tail until the reader scrolls up, when a button brings the latest message back.
- **One project at a time.** The sidebar shows one project, chosen from a popup under its name, with conversations grouped by date and a filter for status, period and provider.
- **Connectors carry a label.** Each saved connector has an optional `label` (`Connector.label` in `connectors.rs`, `serde(default)`, so settings saved before it load unchanged). A person with two Supabase accounts renames them "Conta Gabriel" and "Conta Moreira" from the row's "⋯" menu (Renomear conta) or the connect dialog. The label is only shown. The MCP server name agents see (`mcp__supabase`, `mcp__supabase_2`) comes from `name` and list order (`unique_server_name`), never from the label, so a rename changes no tool id. The row also shows the account a sign-in belongs to (`ConnectorStatus.account`), kept with the token in the Keychain and read only from what the service sends: `email`, `preferred_username` or `name` in the token response's `id_token` or a JWT access token, an `email`/`user` in the response, Notion's `owner` and `workspace_name`, and GitHub's `GET /user` for a pasted token. A service that sends none shows no account. The native session UI does not list connectors, so the label shows only in Settings.
- **Appearance follows Monocode's glass.** The default look is the Ink theme with a pink accent (`#ec4899`): the dark window tint is black at 77%, and the conversation's card paints nothing, so the desktop shows through. The composer and most popups are frosted with `backdrop_blur_marker`. The caret is solid, 1.5 px, in the text's ink, so an idle window has no reason to redraw. The send button (`send_morph.rs`, from Monocode, MIT) is one control: dim when empty, a labelled accent button with text, and an accent Stop square while the agent works with nothing typed; its ink is black or white by the accent's luminance. Text selection is the accent at 35% (20% on light). The look is saved to `native-look.json` in the data folder, because it used to reset on every launch.
- **Terminal placement.** Settings → Geral → Terminal offers bottom, side panel (the default) or title bar, saved in `native-terminal.json`. ⌘J opens or toggles it and ⇧⌘J adds or splits a shell. Closing a terminal whose PTY has a foreground process other than its shell asks first, unless the setting is off.
- **Reply actions and hover.** Under a reply: copy, retry, undo when files changed, and a `⋯` menu for side chat, fork, handoff and second opinion (`message_actions.rs`, `handoff.rs`). One pill glides between hovered rows (`hover_track.rs`). Conversations open side by side (`split_panes.rs`, saved in `split-layout.json`), replies draw Mermaid and KaTeX in a hidden WKWebView cached by content hash (`reply_render.rs`), and side chats stay out of the project's list.
- **Usage popup.** `usage_page.rs` is a centred dialog with cost, tokens and limits, a stacked cumulative area chart and full numbers that count up. Limits add a daily pace for weekly windows: the budget is what's left at the start of the local day divided by the days until reset, with first readings kept in `usage-day-readings.json`. `SIRUS_USAGE_EXTRA_ACCOUNTS` points the host's history at Sirus Code's account profiles, read-only.
- **Corners and hover.** `theme.rs` holds the only corner sizes: `RADIUS_SM` 6, `RADIUS_MD` 10, `RADIUS_LG` 14, `RADIUS_XL` 18. Hover fills are `content(0.07)`, in the sliding pill and on loose buttons.
- **A clean host environment.** Native started from an agent's shell inherits that session's `CLAUDE_*` variables, which would point its agents and usage at that session's account. `backend.rs` removes them before starting the host.
- **Deletions always ask.** Every destructive action goes through one confirmation popup (`native_confirm`), including the Settings pages.

## Browser bridge: agents drive the window's browser

`sirus-host` has no window, so `browser_mcp.rs` used to answer every `browser_*` tool with "the embedded browser is only available in the Mac app". Native has the window, so the host forwards the calls to it (`browser_bridge.rs` in `src-tauri`, `browser_bridge.rs` in `native-spike`).

- **Local window client.** A connection counts as the local window only when its token equals the contents of `<data dir>/native-token` (the file Native writes when it pairs); the peer address is ignored, because `tailscale serve` makes remote devices look like loopback. Only that connection may call `register_browser_client`, answer with `browser_tool_result`, read the bridge events, and use the saved-login commands and `computer_action` that stay denied for every other device. A phone or another computer paired to the same host gets the refusal it got before.
- **Flow.** Native calls `register_browser_client` after each connect (the host also lists the browser tools to agents when started with `SIRUS_BROWSER_CLIENT=1`, which Native sets). An agent's tool call is validated in the host exactly as in the Mac app (URL allow-list, `ref` and selector checks, key list, device and size limits, upload paths inside the workspace or the conversation's attachments, session scoping by token, the Settings switch for agent browser access). It then goes only to the registered connection as the event `browser_tool_request {id, sessionId, tool, args}`, and the host waits 30 s (60 s to stop a recording) for the command `browser_tool_result {id, ok, value | error}` from that same connection. A closed socket or a newer registration fails pending calls at once. With no client registered the tools return the old error.
- **Who shapes what.** Native runs the page scripts (copies of the ones in `browser.rs` and `browser_agent.rs`, in `native-spike/src/browser_js/`) on the conversation's WKWebView and returns what the script returned, or the session state (`BrowserSessionState` JSON); the host turns that into the tool result (`action_value`, `network_entries`, the `{image}` of a screenshot, the device notes). Refs (`data-sirus-ref`, `e1`…) and result shapes are therefore Sirus Code's, and the tool docs stay true.
- **One browser per conversation.** `panel_browser.rs` keeps a `Browser` (tabs, device, colour scheme, zoom, dialog) per conversation, created by the first panel or the first tool call, so an agent works with the panel closed. The web views hang off the window's content view and are hidden unless the panel paints them.
- **Secrets stay out of the agent.** `browser_fill_login` does the vault lookup and the approval card in the host, then sends the values only as the argument of the fixed fill script (`fill_login_page`); the tool result names the fields filled and never a value. The person's key button uses the same path (`login_vault_autofill`). The password form capture runs in the client content world and reaches the host as `login_vault_note_submission`; private tabs never offer to save. Logins live in the Keychain under `Sirus Native browser logins`.
- **Approvals.** The host publishes `login-vault-state` (save offers, agent sign-in approvals) and `computer-state` (computer-use requests). Native shows offers in the panel and the other two as cards above the composer; answers go back with `login_vault_answer_offer`, `login_vault_answer_approval` and `computer_action {type: "respond"}`.
- **Computer use.** The `sirus_computer` MCP server is now registered and served by the host on macOS (before, `computer_mcp::init(.., false)` and desktop-only cfgs left it unreachable under `sirus-host`). Native's bundle is the app macOS attributes Accessibility and Screen Recording to, so those two permissions are granted to Sirus Native. The on-screen indicator and the Esc kill switch need the AppKit main thread and are not in the host; Settings → Computer has Stop and revoke.
- **The host and the window server.** `sirus-host` has no run loop and no window, which breaks two AppKit assumptions. `NSWorkspace.runningApplications` goes stale without a run loop, so `computer.rs` lists processes with `proc_listallpids` and asks `NSRunningApplication` by pid; `computer_launch` waits up to 5 s for the app to appear. `SCContentFilter initWithDesktopIndependentWindow` aborts the process without a window-server connection, so `bin/sirus-host.rs` calls `NSApplicationLoad` at start and sets the activation policy to Prohibited, which connects it without a Dock icon or a menu.
- **Screenshots in the activity tree.** `tool_images.rs` (host) saves each `browser_screenshot` and `computer_screenshot` at the source, to `<data dir>/tool-images/<sha>`, and queues the path per session and tool. `activity.rs` claims it for the matching row as `imagePath`, so the transcript keeps it. In the window (`native-spike/src/tool_images.rs`) the row reads "Captura da tela", and a click opens the picture in the Files panel (`Viewer::Picture`), read through the existing `reply_image` rule.
- **Tree rows.** `step_lines.rs` turns a row into an icon, a verb and a target. The host sends the MCP tool's name (`tool`) and, for browser and computer tools only, what it acted on (`target`: the app, the bundle id, or the page without its query, from `activity.rs` `tool_target`); no other argument reaches a row. A capture's row carries a miniature of the shot.
- **Fonts.** One fixed set, as Monocode's (`native-spike/src/fonts.rs`): the system font, Menlo for code, and for the terminal a JetBrains Mono Nerd Font when installed, else Menlo. Settings offers no family or size choice, only the interface scale.
- **Provider paths.** Settings → Provedores hides the executable path behind a folder button, with its label and the detected path. A value that cannot name an executable (an email, a sentence) is refused, and one already saved is removed on load: it made the CLI read as not installed and blocked its sign-in.
- **Settings layout.** A page's title and actions sit on a bar at the top of the pane, on a rule that runs its whole width; the description and content scroll under it, left-aligned up to 1040 px. A conversation with nothing in it shows its project's icon and a line in the middle, with the composer at the bottom. A pending handoff is a shelf on the composer's top edge.
- **Project robots.** `project_avatar.rs` draws a glossy head with a dark visor in one of eight shapes and the project's colour, replacing the pixel sprite. The body is an SVG cached per shape, colour and size; the eyes are painted on it, so a blink or glance needs no new image. The shape is saved in the `accessory` field, whose allowed values now include the shapes; an older accessory falls back to the name's default shape.
- **New tab field.** `new_tab_field.rs` paints letters cell by cell with `paint_glyph`, forming the project's robot in its colour. The pointer brightens it and a click sends a wave for 2.4 s; between events no frame is requested, and Reduce Motion leaves it still. ⌘N goes to an open tab that is known to be empty instead of creating another; a conversation not loaded yet does not count as empty.
- **Icons.** The interface icons are Solar Line Duotone, credited in `native-spike/ICONS-NOTICE.md`. `theme::icon` lands every size on one scale: 12, 14, 16, 18 or 24 px. The Codex mark is Monocode's.
- **Settings.** The menu sits on the window's chrome like the app's sidebar, with the page in a rounded card; Back and search stay put while the page list scrolls. A page's title bar shares the content's width, so its actions end where the cards end. Settings pages that change saved values offer Restaurar padrões, which sends the settings without those keys so the host fills in its defaults.
- **Shortcuts.** A row of Atalhos records new keys, refusing keys another binding or the window holds and those macOS keeps. `settings_pages::shortcut_route` turns a moved binding's new keys back into the ones the window's key handler knows, and silences the old ones.
- **Notifications.** The headless host has no bundle for the notification center, so it emits `notification-native` and the window plays the sound and shows the banner (`native_notify.rs`). Clicking a banner opens the app but not the conversation.
- **Models.** Claude Code's catalog lists only aliases, so `claude_catalog` in `shell.rs` names them with their versions and adds the earlier models the CLI takes by full name. The versions live in a table a new CLI release can outdate, and being listed does not prove the account can use a model.
- **Working composer.** While the agent works, the project's robot walks along the composer's top edge over a line of letters in its colour (`new_tab_field::ledge`); Reduce Motion leaves it out.
- **Pull requests.** `pull_requests_page.rs` is a tab in the title bar, reached from the footer and the palette: list, detail, merge, close, comments, checks and diff through `pull_request_action`. Create PR lives in the Changes panel. Pins, unread marks, review threads and the watch list are not ported.
- **First run.** `first_run.rs` shows four steps over the letters robot on the first launch of an install with no projects, remembered in `native-first-run.json`; Settings → Geral replays it.
- **Global search.** ⌘⇧F and the palette search every conversation through `transcript_action`, from 3 characters (`global_search.rs`).
- **Git, tasks, files and links ported.** The Changes panel generates a commit title (`commit_title_action`, one job at a time, dropped if the person typed meanwhile) and offers Commit e Push and Push; pushing is never implicit, so both end in an inline confirmation, as in React. The subagent card sends a running foreground subagent to the background (`background_subagent`). The Files tree moves an entry to the Trash (`trash_workspace_entry`) behind the shell's confirmation, from a button on the row's hover (React uses a context menu). The Files tree and Changes follow the disk through `workspace_follow.rs` (`workspace_watch`, one view per panel, released when the panel is dropped). Prompt links (ADR-122): macOS delivers `sirus://` to the window, the host checks it with the new `resolve_prompt_link` (the same parser and project matching as `take_prompt_link`, which stays desktop-only because its pending slot is filled by the Tauri deep-link plugin), and the prompt lands in the composer of an empty conversation of the matched project, never sent; "Copiar link do prompt" is a palette command over `build_prompt_link`. `bundle.sh` registers the scheme with `CFBundleURLTypes`. Sirus Code registers the same scheme, and Launch Services keeps one default handler per scheme, so which app opens a link is macOS's choice, not the links'.
- **Not in Native yet.** Several computers (it needs a TLS client, a second connection and routing of commands that stay on this Mac) and so importing a moved conversation; the pull requests page; updating the app. The simulator (`simulator.rs`) has no agent tools, as in Sirus Code.

## Remote access: other devices reach this Mac through a second listener

Settings → Conexões is Sirus Code's page (ADR-080, ADR-132), run by the same `remote.rs`. The host used to serve the window and nothing else, bound to loopback, so a phone could not reach it and the address shown was `127.0.0.1`. It now has two listeners (`sirus-host serve --local-port 7811 --port 7711 --https-port 8443 --label "Sirus Native" --ui-dir …`).

- **The window's listener** is `127.0.0.1:7811`, always on, with the same router and the same `native-token` rule. Turning remote access off never touches it, so the window keeps working (`has_local_listener` replaced the old refusal of `setEnabled false`).
- **The devices' listener** is `remote.json`'s `enabled`, on `0.0.0.0:7711` with the Mac app's peer filter (loopback and Tailscale addresses only, Origin check, one-time codes, hashed tokens). "Permitir outros aparelhos" starts and stops it, which also closes every device socket. The setting is read from `remote.json`; a file written by the older host (no `windowed` flag, `enabled` forced on) is read as off once, so updating never opens the Mac to the tailnet by itself. Keep-awake runs `caffeinate -s -w <host pid>` as in the Mac app, so it ends with the host.
- **Beside Sirus Code.** Different ports (Sirus Code 7710, Native 7711), a different data folder, `remote.json`, host id and tokens, so a device paired to one is simply unknown to the other (and the phone lists them as "<Mac>" and "<Mac> (Sirus Native)"). `tailscale serve` keeps one handler per HTTPS port and Sirus Code holds 443, so Native serves its secure address on 8443 (`https://<mac>.<tailnet>.ts.net:8443`) and only ever turns off its own. A busy port shows as the page's error instead of failing silently. Origins carry the port (`own_https_authority`), so the phone page on :8443 passes the Origin check; cross-computer pairing from another Sirus's page is not offered for a port other than 443.
- **The window is not a device.** Its token's hash is found by `native-token`; `status` leaves it out of the list and out of the 10-device limit, and `rename` and `revoke` refuse it. `sirus-host pair window` (control request `pairWindow`) makes the code Native redeems for itself, which works with other devices off.
- **The phone's UI** is the web app from `npm run build` of the same checkout, served by the host from `--ui-dir`. `bundle.sh` builds `dist/` when missing (or with `BUILD_UI=1`) and copies it to `Contents/Resources/ui`; running from `target/release` without a bundle falls back to the repository's `dist/`. It adds about 97 MB to the app (34 MB gzipped; 39 MB of that is the Office previews' WebAssembly).
- **Pairing popup.** `settings_pair.rs` is `PairDeviceDialog.tsx`: hero, iPhone app / browser switch, the QR code drawn with round modules and the Sirus mark (the `qrcode` crate, the host's own), the six digits, the steps, the countdown, copy link, new code, and the "connected" view that names the device that used the code (found by polling `remote_action status` every two seconds while the popup is open). Devices can be renamed and removed (a confirmation first), alerts can be tested, HTTPS is turned on and off, and keep-awake has its switch, all as `remote_action`.
- **Public route.** `native.siruscode.com` is a second hostname on the Mac's Cloudflare tunnel (`sirus-mac`), pointing at `127.0.0.1:7711`, behind its own Access application with the same two policies as `mac.siruscode.com` (ADR-155). `remote-public.json` in Native's data folder names it, so a pairing code shows the public link. It answers only while Settings → Conexões allows other devices.

## Consequences

- Two windows exist until the rewrite ends. Anything new in Sirus Code has to be ported.
- Local work that the host doesn't offer (a commit's files, whole-project file search) runs `git` from the window, so it only works on this machine.
- Syntax highlighting (tree-sitter) adds about 8 MB to the app.
- Not done yet: the Simulator pane, Create PR and Watch PR in the Environment panel, the "Other computers" list of Settings → Conexões (this window drives only its own host), and per-project colour themes.
- The app is signed with a stable local identity, so macOS remembers "Always allow". The code is not notarized or released.

## Testing note

The local window token also runs what a paired device may not: remote access settings and dictation (`browser_bridge.rs`, `run_local`). Real clicks posted as HID events reach GPUI, so flows can be tested end to end; synthetic per-process clicks do not.
